# Codex Workloop

把 Codex 任务验收、原生定时任务、PGH 风格的日报与周报串成一个可回放的工作流。一个任务做不完时，下一次执行可以找到剩余要求和原始验收证据。

> Evidence-backed task handoff, native Codex scheduling, and daily/weekly reports.

## 三步复现

需要 Python 3.9 或以上和系统时区数据。样例用两行虚构库存，无需模型 API 或账号。

```bash
python3 demo.py replay
python3 -m unittest -v
```

回放打印状态目录、日周报哈希、接续断点和结项回执。

| 样例时间（上海） | 行为 | 可核对的结果 |
| --- | --- | --- |
| 11 月 22 日，周日 | 校验库存 CSV，提交第一项证据 | 提前结项被拦住，仍缺补货清单 |
| 11 月 23 日 00:00 | 按半开时间窗生成日报和周报 | 周日两份报告都保留未完成项 |
| 11 月 23 日上午 | 校验日报哈希，从剩余项接续 | 算出待补货 SKU，校验文件后签发结项回执 |
| 11 月 24 日 00:00 | 生成周一日报 | 周一日报回读结项回执，周日报告保持原样 |

报告使用上海零点日界线，周报覆盖周一到周日，以周日命名。代码把带时间戳的验收事件写入 SQLite，按期末截取事件生成报告。接续读取已发布的日报和当前未完成项。结项重新核对所有证据文件的 SHA-256。

## 接入 Codex 原生定时任务

先准备首日样例，使用新的目录。

```bash
python3 demo.py seed --state-dir .workloop/demo
```

在 Codex 的原生定时任务中，将运行环境设为本地。任务提示词可以使用下面这一段，把两个占位路径换成你的绝对路径。样例固定使用周一零点作为逻辑时间。运行历史记录实际调用时间。

> 在本地执行 `python3 <仓库路径>/demo.py report --state-dir <状态目录>`。核对 JSON 含周日的日报和周报，回报两个周期及哈希。

该任务运行过一次后，继续第二天。可以先暂停样例定时任务，避免重复运行固定场景。

```bash
python3 demo.py finish --state-dir .workloop/demo
```

日常使用的调度命令是 `python3 workloop.py --state-dir <状态目录> report`。该命令使用实际时间，生成已闭合期间的报告。用 `python3 workloop.py --help` 查看 `start`、`accept`、`resume`、`complete` 等命令。[Codex 原生定时任务文档](https://learn.chatgpt.com/docs/automations?surface=app)

## 验证记录

- 本地回放使用固定逻辑日，覆盖中途交付被拦、跨日续接、最终验收和报告冻结。
- 一次 Codex 原生自动化运行调用了同一演示的报告步骤。随后第二天的演示读取了该次生成的日报，完成剩余工作并签发回执。
- 测试覆盖零点边界、重复调度、文件恢复、产物篡改、过期补写和越界文件引用。

这个公开实现使用独立状态目录和虚构样例。报告由验收事件确定性生成，包含工作、证据与待续事项。下一次执行由调用方显式接续。本版每个状态目录承载一项任务。
